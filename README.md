# Bucksley website

[bucksley.ai](https://bucksley.ai/) is the Bucksley landing page, [download page](https://bucksley.ai/download/) (coming soon until the first signed Mac build), [MCP setup](https://bucksley.ai/mcp/), [help](https://bucksley.ai/help/) and [privacy](https://bucksley.ai/privacy/) pages. The app source is in [protomota/bucksley](https://github.com/protomota/bucksley).

It is a static site on the house Protomota app-site template (copied from graphley-site), re-skinned with Bucksley's "Afterhours" design. It is hosted on Cloudflare Pages (project `bucksley`), deployed from GitHub `main` with build command `bash tools/cf-build.sh` and output directory `dist`. The build copies the site into `dist/` (leaving out `tools/`, `functions/`, `downloads/` and this README) and runs IndexNow. Headers are in `_headers`, redirects in `_redirects`. `functions/_middleware.js` (limited by `_routes.json`) sets the analytics consent cookie and streams `/downloads/*` from the R2 bucket `bucksley-downloads`, bound to the project as `DOWNLOADS`. bucksley.si and www.bucksley.ai 301 to bucksley.ai through zone Redirect Rules.

## Pages

The HTML pages and `llms.txt` are generated by `tools/build-site.py` (shared head, header and footer; the Discord, newsletter and More from Protomota tail is `tools/family.html`). Edit the generator and run `python3 tools/build-site.py` rather than editing the pages by hand. The hero's working preview (Afterhours, Evergreen and Almanac themes, light and dark) and the iPhone review inbox run on `assets/site.js` with made-up sample data. `tools/render-icons.js` renders the icons from `mark.svg` and `tools/mark-small.svg`, and `tools/render-social-card.js` renders `social-card.png` from `tools/social-card.html` (both need Playwright). Nothing in `tools/` is deployed.

## Releases

Until the first release, every page says "Coming soon" and the JSON-LD offer is `PreOrder`. Mac releases are published by `bucksley/scripts/release-mac.sh`. It builds, signs, notarizes and staples the DMG, signs the Sparkle feed, copies `Bucksley-VERSION.dmg` into `downloads/` (git-ignored) and the feed to `/appcast.xml`, then runs:

```sh
tools/set-release.sh VERSION BUILD SHA256 BYTES
```

That checks the staged DMG against the SHA-256 and size (`pending` is accepted for both as a placeholder) and regenerates every page with `tools/build-site.py --release`: the header and hero switch to "Download for Mac", the download page gets the installer, install guide and checksum, and the JSON-LD offer becomes `InStock` with `softwareVersion` and `downloadUrl`. Later runs read the current release back from the download page. The iPhone app stays "coming soon" until its App Store release.

Installers are served from R2, not git. Upload the DMG **before** pushing the appcast and pages:

```sh
npx wrangler r2 object put bucksley-downloads/Bucksley-VERSION.dmg --file downloads/Bucksley-VERSION.dmg --remote --content-type application/x-apple-diskimage
curl -sI https://bucksley.ai/downloads/Bucksley-VERSION.dmg   # 200, application/x-apple-diskimage, the right length
```

Then commit `appcast.xml` and the regenerated pages and push `main`. Older DMGs stay in the bucket so earlier appcast entries keep working.

## Sitemap dates and IndexNow

`tools/indexnow.mjs` runs at the end of every Cloudflare build. It compares each page in the sitemap with the page that is live, writes `<lastmod>` into the deployed sitemap (today for a page whose words changed, otherwise the date already live), and on a production build of `main` submits the changed pages to IndexNow so Bing re-reads them within minutes. Preview builds only print what they would submit. Keep `66365049776433ceca35572e03fca658.txt`: IndexNow checks it to confirm the site sent the request.

## Analytics

`assets/analytics.js` loads Google Analytics only after a visitor allows it. The measurement ID is `GA` in `tools/build-site.py` (`G-PENDING` until the GA4 property exists), the Search Console token is `GSC`; set them and regenerate the pages.
